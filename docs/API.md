# API Rust-ядра и JNI

Актуальные определения: [Rust core](../crates/search-core/src/lib.rs), [JNI](../crates/search-jni/src/lib.rs), [Kotlin bridge](../android/app/src/main/java/dev/tgfeature/search/NativeBridge.kt). Формат файлов — [Snapshot v1](../contracts/SNAPSHOT_FORMAT.md).

## Методы Kotlin NativeBridge

Все методы возвращают JSON-строку. `NativeBridge.value` проверяет `ok` и возвращает `value`, либо выбрасывает исключение с текстом `error`.

| Метод | Вход | Успешное `value` |
|---|---|---|
| `version()` | — | Строка версии Rust core, сейчас `0.1.0` |
| `tokenize(path, text)` | Абсолютный путь tokenizer, исходный запрос | `input_ids`, `attention_mask`, `token_type_ids` |
| `open(path)` | Папка распакованного снимка, не ZIP | `{handle, manifest}` |
| `facets(handle)` | Открытая сессия | `{chats:[{id,name}], senders:[{id,name}]}` |
| `search(handle, request)` | Сессия и JSON ниже | Массив результатов |
| `cancel(handle)` | Открытая сессия | `null` |
| `close(handle)` | Handle | `null`; повторное закрытие допустимо |

`tokenize` сам добавляет `query: ` и усечение до 512 токенов. Его cache хранит один tokenizer по пути; при смене пути он перезагружается. Выполнение модели — следующий отдельный шаг Kotlin.

Facets ограничены 1000 чатами и 1000 отправителями. При нескольких именах одного ID выбирается строковый `MAX`, не обязательно самое новое имя. Username в список choices сейчас не входит; null-отправители не получают отдельную опцию.

### Конверт ответа

```json
{"ok": true, "value": {"handle": 1, "manifest": {}}}
```

Здесь пустой manifest — сокращение примера, не валидный снимок. Ошибка:

```json
{"ok": false, "error": "invalid session handle"}
```

Тексты ошибок не имеют стабильных числовых кодов. Не стройте логику клиента на точном английском сообщении. Числовой handle действует только внутри процесса, не сохраняется на диск и не является указателем памяти.

## SearchRequest

```json
{
  "text": "спящий человек",
  "vector": null,
  "embedding_space": null,
  "filters": {
    "chat_id": "demo",
    "sender_id": "alice",
    "topic_id": null,
    "from_date": 1700000000,
    "to_date": 1730000000
  },
  "top_k": 10
}
```

Этот пример запускает **только лексический** поиск. Для гибридного замените `vector` на 384 конечных нормализованных числа и задайте точный `embedding_space` из манифеста. Префикс `query: ` применяется при кодировании вектора; поле `text` содержит исходный текст для FTS.

| Поле | Правила |
|---|---|
| `text` | Обязательно, до 8192 UTF-8 байт; может быть пустым для semantic-only CLI |
| `vector` | null/отсутствует либо 384 Float32-значения; квадрат нормы отличается от 1 не более чем на 0,02 |
| `embedding_space` | Должен совпадать со снимком при передаче вектора |
| `filters` | По умолчанию пустой объект; все поля необязательны/null |
| `top_k` | По умолчанию 10, допустимо 1–100; UI использует 20 |

Filters соединяются через AND у одного сообщения. Даты — Unix seconds UTC с включёнными границами; `from_date > to_date` — ошибка. В UI конец выбранного дня преобразуется в последнюю секунду этого дня UTC. `sender_id` фильтрует ID, не username. `topic_id` поддерживается ядром, но отдельного поля темы в текущем UI нет.

Rust input-структуры используют `deny_unknown_fields`: новые поля требуют согласованного изменения клиента и ядра. Запрос без вектора и без лексических токенов возвращает пустой массив. UI дополнительно запрещает пустой запрос и требует совместимую импортированную модель.

## Результат

```json
[
  {
    "image_id": "sleep",
    "description": "Мужчина спит на диване.",
    "thumbnail": null,
    "score": 0.03278688524590164,
    "sources": [
      {
        "chat_id": "demo",
        "chat_name": "Демонстрационный архив",
        "sender_id": "alice",
        "sender_name": "Алиса",
        "username": null,
        "date": 1700000000,
        "link": null
      }
    ]
  }
]
```

`thumbnail` — относительный проверенный путь внутри снимка. `description` — основная сцена из `images`, даже если смысловая ветвь дала главный вклад. Объяснение релевантности и исходные оценки отдельных ветвей в API не возвращаются.

`score` — сумма RRF, не вероятность и не исходный cosine. `sources` содержит до 50 подходящих сообщений от новых к старым. Тема, message key и подпись хранятся в SQLite, но в объект Source сейчас не возвращаются. UI открывает только ссылки с `https://t.me/` или `tg://`; отсутствие ссылки допустимо.

## CLI

CLI использует Rust core без JNI-конверта: JSON результата/манифеста пишется в stdout, ошибка — в stderr с exit code 1.

```bash
source scripts/env.sh
cargo run --locked -p search-cli -- validate data/demo-v1
indexer/.venv/bin/tg-index query models/e5-small 'спящий человек' data/request.json
cargo run --locked -p search-cli -- search data/demo-v1 data/request.json
```

`tg-index query` формирует правильный вектор на ПК. Чтобы изменить фильтры, редактируйте созданный JSON; не заменяйте его вектор другой моделью. `validate` не исполняет модель и не подтверждает качество описаний — проверяет файловый контракт и данные.

## Потоки, ошибки и отмена

JNI-вызовы синхронные; вызывайте их вне UI-потока. Внутри одной сессии поиск/facets сериализованы Rust mutex. `cancel` выставляет флаг без ожидания mutex снимка. Новый search сбрасывает флаг, поэтому cancel перед запуском не гарантирует отмену будущего поиска.

`close` немедленно делает handle недоступным для новых вызовов, но ресурсы продолжают жить у уже исполняющегося вызова через Arc. Максимум зарегистрированных сессий — 8. Kotlin ViewModel дополнительно сериализует импорт и поиски, отменяет Job и отсеивает устаревшие ответы через номер generation.

Флаг ядра не останавливает ONNX Runtime, токенизацию или все SQLite-операции. Эти ограничения важны при разработке мгновенного поиска и обработке lifecycle; они ещё не покрыты полноценными стресс-тестами.

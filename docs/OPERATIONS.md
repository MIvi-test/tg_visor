# Сборка, данные и диагностика — v0.1.1

Команды выполняются из корня репозитория, если не указано иное. Описание алгоритмов — в [ARCHITECTURE.md](ARCHITECTURE.md), интерфейсы — в [API.md](API.md), фактические проверки — в [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

## 1. Подготовить инструменты

Поддерживаемая среда сборки: Linux x86_64. APK сейчас содержит только arm64-v8a, minimum Android API 26; подключённый телефон имеет API 34. x86_64 Rust target установлен для дальнейших проверок, но соответствующий Android `.so` ещё не поставляется.

```bash
./scripts/bootstrap.sh
source scripts/env.sh
./scripts/download-model.sh
```

Bootstrap скачивает локальные инструменты и принимает Android SDK licenses. Gradle и JDK закреплены и проверяются по SHA-256; веса и tokenizer проверяются скриптом скачивания. Используйте `source scripts/env.sh` в каждом новом терминале: системные Java 27 и Rust 1.99 не являются toolchain проекта.

| Путь | Назначение |
|---|---|
| `.tools/` | Rust 1.90, JDK 17, Gradle 8.11.1, SDK 35 / NDK 27.2, кеши |
| `indexer/.venv/` | Python 3.12 и закреплённые runtime-зависимости |
| `models/e5-small/` | `model.onnx`, `tokenizer.json`, создаваемый `model.json` |
| `data/` | Рабочие каталоги, снимки, ZIP и результаты probes; не коммитить |
| `android/app/build/outputs/` | Собранные APK |

После установки зависимостей модель и поиск работают локально. Первое скачивание требует сети и нескольких гигабайт диска. Ollama/VLM не устанавливаются bootstrap-скриптом; выбранный runtime описания картинок готовится отдельно.

## 2. Собрать приложение и проверить код

```bash
source scripts/env.sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
indexer/.venv/bin/python -m unittest discover -s indexer/tests -v
./scripts/build-android.sh
```

Из папки `android/`:

```bash
./gradlew --no-daemon testDebugUnitTest lintDebug
```

Gradle `preBuild` вызывает Rust-сборку через `scripts/build-native.sh`; отдельная ручная копия `.so` не нужна. Нативная библиотека — `libtg_search.so`, Android API linker level 26, ELF alignment 16 KiB. Gradle использует локальный NDK, ONNX Runtime входит в APK, веса модели — нет.

| Артефакт | Путь |
|---|---|
| Приложение | `android/app/build/outputs/apk/debug/app-debug.apk` |
| Device probe | `android/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk` |
| JUnit XML | `android/app/build/test-results/testDebugUnitTest/` |
| Lint | `android/app/build/reports/lint-results-debug.html` |

Готовый APK: [релиз v0.1.1](https://github.com/MIvi-test/tg_visor/releases/tag/v0.1.1). Установите поверх предыдущей версии; модель, архив и настройки сохранятся. В релиз входят APK, SHA256SUMS и описание, без личных данных и весов. Прототип использует debug-подпись. Release signing, CI и обновления через Obtainium ещё не настроены. Не запускайте установку SDK из нескольких процессов одновременно: Gradle тоже может попытаться скачать недостающие пакеты. Сначала дождитесь завершения bootstrap.

## 3. Создать первый снимок без Telegram

```bash
mkdir -p data
indexer/.venv/bin/tg-index pack-model models/e5-small data/e5-small.zip
indexer/.venv/bin/tg-index export contracts/demo-catalog.json models/e5-small data/demo-v1 --dataset-id demo --version 1
cargo run --locked -p search-cli -- validate data/demo-v1
indexer/.venv/bin/tg-index pack data/demo-v1 data/demo-v1.zip
indexer/.venv/bin/tg-index query models/e5-small 'спящий человек' data/request.json
cargo run --locked -p search-cli -- search data/demo-v1 data/request.json
```

`pack-model` создаёт модельный манифест и ZIP, но сам не выполняет inference. `export` и `query` открывают модель через ONNX Runtime. Экспорт/упаковка не перезаписывают существующие выходы: при повторении выбирайте новое имя. Не удаляйте действующие снимки, чтобы устранить эту ошибку.

Демо содержит четыре искусственные записи с настоящими E5-векторами. Оно проверяет передачу данных и поиск, не качество распознавания фото. `demo-v2.zip`, подготовленный во время разработки, дополнительно содержит тестовую графику для превью; его генерация не входит в базовую команду выше.

### Собственный каталог описаний

Можно начать с локальных картинок и вручную подготовленного JSON, не подключая аккаунт. Пример записи:

```json
[
  {
    "id": "local-example-001",
    "scene": "Человек спит на диване с закрытыми глазами.",
    "meaning": "Отдых после рабочего дня.",
    "ocr": "",
    "thumbnail": "media/example.jpg",
    "sources": [
      {
        "key": "local:001",
        "chat_id": "local",
        "chat_name": "Локальный набор",
        "sender_id": null,
        "sender_name": null,
        "date": 1700000000,
        "caption": "",
        "link": null
      }
    ]
  }
]
```

Положите JSON, например, в `data/local/catalog.json`, картинку — в `data/local/media/example.jpg`. Путь превью должен оставаться внутри папки каталога. `scene` и хотя бы один source обязательны, `meaning` и thumbnail необязательны. Для ручных наборов ID должен быть уникальным; exporter сам не вычисляет хеш изображения и не объединяет повторяющиеся записи.

Для `tg-describe` дополнительно требуется поле `image` с путём к картинке. Для уже описанного каталога `image` не нужен: exporter работает с текстами и опциональным превью.

## 4. Подготовить реальный Telegram-архив

Этот путь реализован, но на реальном аккаунте пока не проверен. Используйте явно выбранные чаты. Авторизация даёт пользовательскую сессию аккаунта; allowlist ограничивается нашим кодом, а не отдельным Telegram-permission.

```bash
mkdir -p data
cp -n indexer/config.example.json data/config.json
```

Отредактируйте `chats`; не запускайте оставшийся placeholder. `limit_per_chat` — число просматриваемых сообщений, от 1 до 100000. Даты интерпретируются как UTC; рекомендуемый формат — `YYYY-MM-DD`. `to_date` передаётся как offset истории: чтобы включить весь день, задавайте начало следующего дня. Вручную переданные timezone offsets код сейчас заменяет на UTC, поэтому не используйте их.

### Получить Telegram API ID и hash

Войдите на [my.telegram.org](https://my.telegram.org) по номеру своего Telegram-аккаунта и откройте **API development tools**. Создайте приложение: например, App title `TG Visor`, Short name `tgvisorpersonal`, Platform `Desktop`. На странице приложения появятся **App api_id** и **App api_hash**; для уже созданного приложения используйте существующие значения. См. [официальную инструкцию Telegram](https://core.telegram.org/api/obtaining_api_id).

Это параметры пользовательского API, а не токен BotFather. Для регулярной работы рекомендуем локальный `.env`:

```bash
cp -n .env.example .env
chmod 600 .env
```

Откройте файл редактором и замените примеры своими значениями. Шаблон [.env.example](../.env.example) содержит только `TG_API_ID` и `TG_API_HASH`; регистр важен. `.env` исключён из Git, но не передавайте его в чат и не включайте в архивы доставки. Телефону эти параметры не нужны.

Загрузите файл из корня репозитория в Bash:

```bash
set -a
source .env
set +a
```

Сборщик читает окружение, а не `.env` напрямую. Команды выше экспортируют значения в текущий терминал и его дочерние процессы; в новом терминале повторите загрузку. `source` исполняет shell-код, поэтому загружайте только собственный файл. Альтернатива без хранения параметров на диске — интерактивный ввод через `read` и `export`.

Затем:

```bash
indexer/.venv/bin/tg-collect data/config.json data/archive
./scripts/setup-florence.sh
indexer/.venv/bin/tg-describe data/archive/selected-catalog.json --device cuda
indexer/.venv/bin/tg-index export data/archive/florence-catalog.json models/e5-small data/archive-v1 --dataset-id personal --version 1
cargo run --locked -p search-cli -- validate data/archive-v1
indexer/.venv/bin/tg-index pack data/archive-v1 data/archive-v1.zip
```

### Лимит запросов, логи и прогресс

В `config.json` можно добавить `"requests_per_second": 2`. Значение по умолчанию — 2, диапазон 0,1–20 RPC/с; дробные значения задаются через точку. Для одного запуска настройку можно переопределить:

```bash
indexer/.venv/bin/tg-collect data/config.json data/archive --requests-per-second 1
```

Лимит общий для RPC истории, поиска сущностей, авторизации и скачивания частей медиа, включая повторы и CDN. Между отправками выдерживается интервал без накопления разрешений и всплесков. Это лимит RPC через Telethon, а не TCP-пакетов: соединение, служебные сообщения протокола и транспортные повторы Telethon не регулируются им. Адаптер использует внутренний `_call` закреплённого Telethon 1.40.0; при обновлении зависимости обязательно повторить тесты. Указанный лимит не гарантирует отсутствие ограничений Telegram.

При FloodWait сборщик пишет длительность паузы, ждёт требуемое время и повторяет запрос. Короткие ожидания больше не скрываются внутри Telethon. Шкала показывает просмотренные сообщения относительно верхней границы `число чатов × limit_per_chat`; если история или диапазон дат закончились раньше, завершение может быть ниже 100%. Для текущей картинки дополнительно показывается процент скачивания. Счётчики: новые скачивания, ранее сохранённые источники и RPC. Повторный запуск пропускает известные источники, но снова просматривает заданный диапазон истории.

Логи сразу идут в stderr и `data/archive/collect.log`; файл ротируется при 5 MiB, сохраняются две предыдущие копии, права — `0600`. `--log-file data/archive/custom.log` задаёт другой путь. Раз в 10 секунд во время асинхронного ожидания выводится текущая стадия. Интерактивная авторизация может временно блокировать heartbeat. Названия чатов, usernames, подписи, API hash и содержимое запросов в наши логи не включаются. Ошибка CLI показывает класс исключения, без traceback с приватными данными.

Следить за логом из другого терминала:

```bash
tail -f data/archive/collect.log
```

По умолчанию `tg-describe` использует Florence/EasyOCR и пишет `florence.log`, время картинки и ETA; результат — `florence-catalog.json`. Подготовка и варианты OCR — в [FLORENCE.md](FLORENCE.md). Отдельный backend `--backend ollama` показывает сообщения перед VLM-запросами и пишет `describe.log`/`described-catalog.json`. Сохранённые описания используются повторно только при совпадающем профиле. `tg-index` пишет стадии и прогресс векторизации в stderr, не загрязняя JSON-файлы. Сетевые запросы описания последовательны и локальны; Telegram-лимит к ним не применяется.

Патч применяется только при новом запуске процесса. Чтобы перейти со старого сборщика, остановите его `Ctrl+C` в исходном терминале, дождитесь выхода и повторите ту же команду. `catalog.json` сохраняется после каждого скачанного источника. Не запускайте два сборщика одновременно с одной session/выходной папкой. После прерывания проверьте завершение нового сбора и обновление `selected-catalog.json` перед описанием или экспортом.

### Дополнительный backend Ollama

Следующие параметры относятся только к `--backend ollama`. Перед его запуском локальная VLM-служба должна быть запущена и модель доступна. Клиент явно задаёт `num_ctx=8192`, оставляя место для визуальных токенов и ответа. При HTTP 400 «превышен контекст модели» можно увеличить его для конкретного запуска:

```bash
indexer/.venv/bin/tg-describe data/archive/selected-catalog.json --backend ollama --model qwen3-vl:2b-instruct --context-size 16384
```

### Instruct и бюджет ответа

Для описаний используется `qwen3-vl:2b-instruct` без reasoning; режим thinking и его CLI-флаги удалены. Клиент всегда передаёт `think=false`. Для более сильной модели можно выбрать `qwen3-vl:4b-instruct`; не используйте сокращённые теги `qwen3-vl:2b`/`:4b`, соответствующие Thinking-вариантам. Модель нужно отдельно скачать в запущенную Ollama:

```bash
ollama pull qwen3-vl:2b-instruct
indexer/.venv/bin/tg-describe data/archive/selected-catalog.json --backend ollama --model qwen3-vl:2b-instruct --max-tokens 1024 --timeout 600
```

`--max-tokens` допускает 128–8192, по умолчанию 1024. Чтобы исключить чрезмерно длинную генерацию, схема ограничивает scene 1000 символами, meaning 600, OCR 2000; при большом количестве текста промпт просит основные надписи дословно. Это индекс основных надписей, а не полный OCR длинных документов. Используется repeat_penalty=1.1. Версия промпта — 2; описания версии 1 потребуют повторной обработки. Это верхняя граница генерации, а не обязательная длина ответа. JSON schema требует scene/ocr/meaning; парсер читает только финальный response. Пустой, обрезанный или некорректный ответ повторяется один раз с удвоением бюджета до максимума 8192. Если ошибка сохраняется, обработка останавливается с номером картинки и безопасной причиной. Ответы не попадают в лог. Каталоги имеют отдельную диагностику JSON с номером строки и столбца. Смена имени модели требует новой разметки; кеш предыдущей модели не используется для новых описаний.

Диапазон `--context-size`: 1024–32768. Больший контекст требует больше памяти; повышайте его только при ошибке переполнения. На синтетическом JPEG 2325×2560 запрос занимал 4164 токена и не помещался в серверный контекст 4096. В HTTP-логе теперь показываются статус и безопасная категория ошибки; произвольный текст сервера скрывается, поскольку может содержать приватные данные. Точный лог runtime смотрите локально в терминале `ollama serve` или, для системного сервиса, через `journalctl -u ollama --since '10 minutes ago'`. Для проверки CPU/GPU используйте `ollama ps`; выполнение на CPU может занимать значительно больше времени. Если истёк таймаут, задайте `--timeout 600` (по умолчанию 300 секунд, диапазон 1–3600). Увеличение таймаута не ускоряет обработку. После описаний самостоятельно выгрузите тяжёлую модель через выбранный runtime, если хотите освободить GPU/RAM. Клиент проекта этим не управляет. Сцены и интерпретации желательно просмотреть до массовой индексации.

В `data/archive/` останутся `telegram.session`, `media/`, `catalog.json`, `selected-catalog.json` и `florence-catalog.json`; старый `described-catalog.json` остаётся при использовании Qwen. Папка имеет ограниченные права; сессия не входит в снимок. Не публикуйте каталог, описания, превью или эмбеддинги приватных чатов в открытый репозиторий.

## 5. Перенести модель и архив на телефон

```bash
source scripts/env.sh
adb devices -l
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell mkdir -p /sdcard/Download/TGFeature-demo
adb push data/e5-small.zip /sdcard/Download/TGFeature-demo/e5-small.zip
adb push data/demo-v1.zip /sdcard/Download/TGFeature-demo/demo-v1.zip
```

`adb devices -l` показывает идентификатор устройства: не добавляйте этот вывод в публичные отчёты. Эти команды устанавливают только приложение проекта и копируют выбранные пакеты; не сбрасывают настройки и данные других приложений.

В приложении:

1. «Скачать E5-small из интернета» → подтвердите загрузку около 136 МБ по HTTPS. Либо «Модель» → выберите `e5-small.zip`.
2. «Импорт архива» → выберите ZIP снимка.
3. Дождитесь проверки и появления статуса архива.
4. Введите запрос; раскройте «Фильтры», при необходимости выберите чат, отправителя и даты, нажмите «Найти». Последние 20 запросов сохраняются локально в «Истории»; список можно очистить. Тема переключается кнопкой «Светлая/Тёмная».

Файловый диалог начинает выбор с «Загрузок», без MIME-фильтра; это исправляет скрытие ZIP на Xiaomi. Неподходящий файл всё равно отклоняется по содержимому. Все файлы внутри ZIP должны лежать непосредственно в корне, без папки-обёртки.

Импорт архивов не создаёт Telegram-сессию. Нажатие источника открывает `tg://` в установленном Telegram-клиенте (в том числе совместимом стороннем клиенте). Если клиентов несколько, выбор обрабатывает Android; если обработчика нет, открывается HTTPS-страница. Для доступа к исходному сообщению нужен аккаунт с доступом к этому чату. На недоступный или удалённый пост ссылка может уже не работать, хотя локальный результат остаётся.

## 6. Доставка новых версий через папку

После подготовки и проверки нового снимка с тем же dataset ID и увеличенным номером версии:

```bash
indexer/.venv/bin/tg-index publish data/archive-v1 data/delivery
```

Publisher создаёт `snapshot-1.zip`, затем `latest.json`. Он не вызывает Rust validator сам. Для следующего снимка задайте новую папку и `--version 2` при экспорте; имя пакета берётся из версии. Не используйте одну папку доставки для разных dataset с совпадающими номерами версий.

Настройте выбранный Syncthing-клиент отдельно: ПК отправляет папку доставки, телефон получает. В приложении укажите её через «Папка обновлений», потом нажмите «Обновить». Фоновая проверка/скачивание не реализованы. APK обновляется отдельно от данных.

```json
{
  "dataset_id": "personal",
  "version": 2,
  "file": "snapshot-2.zip",
  "size": 123456,
  "sha256": "<64 hex-символа SHA-256 всего ZIP>"
}
```

Это иллюстрация latest-манифеста; используйте созданный publisher файл с реальным хешем и размером. Манифест может приехать раньше ZIP — приложение дождётся следующей ручной проверки. Рабочая SQLite-база и модель не должны синхронизироваться напрямую из приватного хранилища приложения.

Старые импортированные папки сохраняются. Интерфейса отката/уборки нет: для возврата можно вручную импортировать сохранённый совместимый ZIP. Режим «Обновить» пропускает версии меньше или равные текущей; другой dataset надо импортировать вручную.

## 7. Device probe

После сборки обоих APK и подготовки демо/модели/`data/request.json`:

```bash
./scripts/device-test.sh
# Если подготовлен снимок с превью:
./scripts/device-test.sh data/demo-v2
```

Скрипт устанавливает приложение и test APK, передаёт данные в изолированную `files/device-test/` через `adb exec-in`, затем запускает `SmokeInstrumentation`. Он не импортирует эти файлы в пользовательский `files/search/` и не делает основной экран готовым к поиску: пользовательские ZIP импортируются отдельно.

Проверки: версия JNI, E5-запрос «спящий человек», ошибка вектора относительно ПК менее 0,01, первый результат `sleep`, фильтр `bob` и отклонение закрытого handle. При FAIL или отсутствии PASS скрипт возвращает ошибку. Это не полный набор UI/lifecycle-тестов; реальная синхронизация папки этим probe не проверяется.

## 8. Диагностика

| Симптом | Причина / действие |
|---|---|
| `adb: command not found` | Подключите `scripts/env.sh`, проверьте bootstrap |
| `unauthorized` | Разблокируйте телефон и самостоятельно подтвердите USB debugging |
| `INSTALL_FAILED_USER_RESTRICTED` | ОС отклонила установку; разрешите запрос/USB-установку на устройстве, не обходите ограничение командами изменения настроек |
| ZIP не виден | Обновите APK с исправленным picker, откройте «Загрузки» и папку с файлами, а не только «Недавние» |
| `unsupported or empty manifest` | Проверьте корень ZIP, версию формата и непустой снимок через CLI |
| `file integrity failed` | Пакет повреждён/изменён или неполон; снова доставьте проверенный пакет |
| «Модель и архив несовместимы» | Использован другой embedding space; импортируйте соответствующую модель/снимок. Валидный несовместимый снимок может уже стать активным |
| «Пакет ещё не полностью доставлен» | Syncthing не завершил передачу или latest/ZIP не соответствуют друг другу |
| «Установлена актуальная версия» | Версия latest не больше текущей; ручной импорт — отдельный путь |
| Импорт/модель потребляют много RAM | Векторы целиком в RAM; при замене одновременно могут жить старая и новая сессии. Лимиты файла не являются гарантией достаточной памяти |
| Результаты слабые | Проверьте описания/OCR, усечение до 512 токенов и набор запросов; размер модели сам по себе не гарантирует качество |
| «спящий» не совпал с OCR «спит» | FTS без морфологии; этот случай должна покрывать semantic-ветвь |
| Новый экспорт не создаётся | Выход уже существует; частичный результат не перезаписывается. Выберите новое имя, не удаляйте рабочий архив |

Не очищайте данные приложения как первый способ исправления: это удалит локальные модели, снимки и настройки. Храните исходные ZIP и рабочую базу на ПК. После принудительного закрытия незавершённые staging-папки могут остаться: автоматической уборки при запуске пока нет.

Перед передачей отчёта убирайте ключи, session-файлы, серийный номер, реальные подписи и имена из логов. Для воспроизводимых багов используйте небольшой искусственный каталог и укажите версии модели, снимка, APK и Android.

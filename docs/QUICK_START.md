# От картинок до поиска на телефоне

Вам нужны Linux-ПК, Android-телефон и выбранные Telegram-чаты. ПК скачивает картинки, описывает их и собирает базу; телефон получает готовый ZIP. Начните с маленького чата или последних 100–1000 сообщений. Реальное качество описаний ещё предстоит проверить на вашем архиве.

## 1. Один раз подготовьте ПК

Откройте терминал в папке проекта:

```bash
./scripts/bootstrap.sh
source scripts/env.sh
./scripts/download-model.sh
./scripts/build-android.sh
```

Это подготовит инструменты, скачает небольшую модель поиска и соберёт APK. В каждом новом терминале выполняйте `source scripts/env.sh`.

## 2. Выберите чаты и скачайте картинки

```bash
mkdir -p data
cp -n indexer/config.example.json data/config.json
```

Откройте `data/config.json` редактором. Замените placeholder в `chats` на выбранный публичный чат, например `@your_chat`, или ID доступного вашему аккаунту чата. `limit_per_chat` ограничивает число просмотренных сообщений, а не картинок. Для первого запуска оставьте 1000 или меньше. Даты задавайте как `YYYY-MM-DD`; верхняя граница — начало следующего дня.

Потребуются собственные Telegram `api_id` и `api_hash`. Получите их один раз:

1. Откройте [my.telegram.org](https://my.telegram.org) и войдите по номеру своего Telegram-аккаунта.
2. Перейдите в **API development tools**.
3. Заполните форму приложения: например, **App title** — `TG Visor`, **Short name** — `tgvisorpersonal`, **Platform** — `Desktop`.
4. После создания приложения скопируйте **App api_id** и **App api_hash**. Если приложение уже создано, используйте его существующие значения.

Это параметры пользовательского API, не токен бота из BotFather. Официальная инструкция: [получение api_id](https://core.telegram.org/api/obtaining_api_id).

Рекомендуемый способ — сохранить параметры в локальном `.env`, чтобы не вводить их заново:

```bash
cp -n .env.example .env
chmod 600 .env
```

Откройте `.env` редактором и замените пример `TG_API_ID` и placeholder `TG_API_HASH` своими значениями. Названия переменных чувствительны к регистру. Сам `.env` исключён из Git; в репозиторий входит только шаблон [.env.example](../.env.example).

Перед запуском, из корня проекта в Bash:

```bash
set -a
source .env
set +a
indexer/.venv/bin/tg-collect data/config.json data/archive
```

Сборщик сам `.env` не читает: `source` загружает значения в текущий терминал, а `set -a` экспортирует их для запускаемых процессов. В новом терминале повторите загрузку файла; повторно копировать шаблон не нужно. Используйте только собственный `.env`, поскольку Bash исполняет его содержимое. Не отправляйте файл в чат; телефону эти параметры не нужны.

Сборщик покажет шкалу сообщений, число скачанных картинок и текущую стадию. Лог сохраняется в `data/archive/collect.log`; его можно открыть командой `tail -f data/archive/collect.log` в другом терминале. По умолчанию отправляется не более 2 RPC/с; добавьте `"requests_per_second": 1` в конфиг для более медленного сбора. Картинка может требовать нескольких запросов. При FloodWait приложение явно сообщит о паузе и продолжит после ожидания. Подробности — в [руководстве](OPERATIONS.md#лимит-запросов-логи-и-прогресс).

Если используете Fish, вместо Bash-блока загрузки `.env` запустите:

```fish
bash -c 'set -a; source .env; set +a; exec indexer/.venv/bin/tg-collect data/config.json data/archive'
```

Collector запросит локальную авторизацию Telegram. Коды и пароль не отправляйте другим людям. Сессия сохраняется на ПК; телефонному приложению она не нужна.

## 3. Получите описания и соберите базу

Теперь описания готовит компактная Florence-2, надписи извлекает EasyOCR ru/en. Один раз установите локальные зависимости и скачайте веса:

```bash
./scripts/setup-florence.sh
```

Для небольшой пробы можно выполнить `tg-describe` с `--limit 10`; она запишется отдельно. Полный цикл разметки и базы:

```bash
indexer/.venv/bin/tg-describe data/archive/selected-catalog.json --device cuda
indexer/.venv/bin/tg-index export data/archive/florence-catalog.json models/e5-small data/personal-v1 --dataset-id personal --version 1
cargo run --locked -p search-cli -- validate data/personal-v1
indexer/.venv/bin/tg-index pack data/personal-v1 data/personal-v1.zip
```

Для команды Cargo нужны инструменты из `scripts/env.sh`: в Fish выполните её в Bash-терминале, предварительно загрузив `source scripts/env.sh`. Команды разметки и экспорта работают напрямую и в Fish. Когда база с такой версией уже существует, задайте новое имя папки и больший `--version`.

Florence создаёт английские описания сцен, без thinking и интерпретации шуток. Многоязычный E5 кодирует их для поиска русским запросом. OCR и подписи сообщений дают отдельный поиск по словам. После подготовки весов разметка работает без интернета; Ollama не нужна. Подробные настройки, ограничения и вариант Qwen — в [руководстве Florence](FLORENCE.md).

Готовый файл — **`data/personal-v1.zip`**. Это база поиска с описаниями и превью. Не передавайте Telegram session или всю папку `data/archive` на телефон. Для повторного экспорта используйте новое имя папки и увеличивайте версию.

Хотите сначала проверить приложение без Telegram и VLM? Выполните демонстрационные команды из [README](../README.md#первый-автономный-поиск).

## 4. Установите приложение и передайте ZIP

Без ADB скачайте `tg-visor-v0.1.1-arm64-debug.apk` из [релиза v0.1.1](https://github.com/MIvi-test/tg_visor/releases/tag/v0.1.1) на телефон, откройте файл и разрешите установку для используемого браузера или файлового менеджера. Для обновления установите APK поверх предыдущего, сохранив модель, архив и настройки. Это тестовая debug-сборка для Android 8+ (arm64).

При включённой USB-отладке и подтверждённом подключении:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell mkdir -p /sdcard/Download/TGFeature
adb push data/personal-v1.zip /sdcard/Download/TGFeature/personal-v1.zip
```

Можно скопировать ZIP обычным USB-переносом файлов в «Загрузки/TGFeature». Это приватный архив: используйте личный транспорт.

Откройте **tgVisor**:

1. Нажмите **«Скачать E5-small из интернета»** и подтвердите загрузку примерно 136 МБ. Лучше по Wi-Fi. Приложение проверит файлы и покажет «E5-small · INT8 · загружена».
2. Нажмите **«Импорт архива»**, откройте «Загрузки/TGFeature» и выберите `personal-v1.zip`.
3. Дождитесь появления количества картинок, версии и даты импорта.
4. Введите «спящий человек» и нажмите **«Найти»**. Раскройте **«Фильтры»**, чтобы выбрать чат, отправителя или диапазон дат. **«История»** позволяет вернуть прошлый запрос; её можно очистить.
5. Нажмите на источник результата: приложение откроет пост в Telegram через `tg://`. Если совместимого клиента нет, откроется сайт. Ваш Telegram-аккаунт должен иметь доступ к сообщению.

Альтернатива интернет-загрузке модели: на ПК выполните `tg-index pack-model` по [инструкции](OPERATIONS.md), перенесите `e5-small.zip` и импортируйте кнопкой «Модель». После подготовки поиск работает без интернета. Тема переключается кнопкой «Светлая/Тёмная» и сохраняется.

## 5. Когда появятся новые картинки

Повторите сбор и описания, экспортируйте в `data/personal-v2` с `--version 2`, проверьте и упакуйте. Перенесите новый ZIP и импортируйте вручную. Модель повторно скачивать не нужно, если артефакт тот же.

Для регулярной доставки есть [обновления через папку](OPERATIONS.md#6-доставка-новых-версий-через-папку): ПК публикует ZIP и `latest.json`, внешний Syncthing доставляет папку, а вы нажимаете «Обновить». Синхронизация настраивается отдельно; фонового обновления пока нет. Не синхронизируйте открытую SQLite-базу приложения.

Если ZIP не виден, импорт не проходит или поиск недоступен, см. [диагностику](OPERATIONS.md#8-диагностика). Исходные ZIP сохраняйте на ПК: автоматической уборки и отдельной кнопки отката пока нет.
